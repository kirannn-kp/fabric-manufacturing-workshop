# Facilitator guide

Use the [setup checklist](environment-setup.md) one week before the workshop. Rehearse all paths one day before and use the [answer key](answer-key.md) at the checkpoints. Send team assignments and private workspace/report links ahead of time. Keep a single untouched baseline separate from teams' work.

Aim for teams of 3–4. Assign a driver, a navigator, and an evidence checker; rotate between labs. If only one member has edit access, they drive while the team verifies each result. Have one facilitator drive and another handle private access requests if staffing allows.

| Checkpoint | Ask or check |
|---|---|
| Day 1 after Lakehouse | Show the inventory file and table. Explain how you verified 180 rows. |
| Day 1 after events | Show two repeated-fault machines and explain why High severity is filtered separately. |
| Day 1 close | Show one corrected or better-defined answer. Record which fallback teams used. |
| Day 2 model | Verify the plant relationships, supplier relationship, and measure descriptions. |
| Day 2 report | Get 12 orders with no cross-filters; confirm one supplier tooltip. |
| Day 2 use-case checkpoint | Privately record priority use case, PoC status, blocker, and required support. |
| Day 2 close | Compare one improved visual and limitation from each team. |
| Day 3 close | Confirm each PoC next action has an owner and a date. |

Use the [agendas](../workshop.md) to pace the day. If an optional feature doesn't work after a short check, move the whole group to its fallback. For support, see [common errors and recoveries](../docs/troubleshooting.md). Do not fix timing by removing the evidence or debrief steps.
